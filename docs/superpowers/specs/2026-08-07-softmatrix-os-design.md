# Softmatrix OS 产品需求文档（PRD）与实现路线图

- **状态**：已确认，待实施计划评审
- **日期**：2026-08-07
- **产品名称**：Softmatrix OS
- **上游项目**：[Cloudflare OS](https://github.com/cloudflare/cloudflare-os)
- **上游基线**：`0eaec6c5e8fc6b3298ea1aa73bf5c3e47b923c7f`
- **许可证**：Apache License 2.0，与上游保持一致

## 1. 摘要

Softmatrix OS 是基于 Cloudflare OS 的企业级开源 AI 工作环境。它保留上游的 Agent、
Gadget、Blueprint、Gatekeeper、沙箱隔离、协作和 capability-based security 架构，重点补齐：

1. 简体中文与英文的完整产品体验；
2. 面向企业的通用 OIDC SSO；
3. 组织共享模型、可控 BYOK 和模型策略治理；
4. Softmatrix OS 品牌与长期上游同步机制。

一期采用“模块化增强型分叉”：把国际化、统一身份和模型策略放在清晰的外围模块中，
只对 Workshop Backend Kernel 和共享 RPC 做必要且小规模的修改。该策略兼顾交付速度、
安全边界、代码审查和持续合并上游更新的成本。

## 2. 背景与上游现状

Cloudflare OS 已经提供：

- React 19、Vite 和 Kumo UI 构成的单页前端；
- 基于 Cloudflare Workers、Durable Objects 和 Cap'n Web RPC 的 Workshop Backend；
- Agent、Gadget、Blueprint、Gatekeeper 和 Human-in-the-loop 工作流；
- 用户名/密码登录、Cloudflare Access，以及 Google、GitHub、Cloudflare OAuth 登录；
- OpenAI、Anthropic、Google、Workers AI 和 Ollama 模型接入；
- 用户自带 API Key，以及基于 Cloudflare AI Gateway 的部署级共享模型模式。

因此，一期并非从零建设 SSO 和多 LLM，而是：

- 为现有英文界面建立可持续的国际化体系；
- 在现有认证入口之上增加标准企业 OIDC，并统一登录策略；
- 把已有多模型能力产品化为可治理的组织模型目录与 BYOK 策略；
- 将零散品牌常量收敛为 Softmatrix OS 品牌配置。

## 3. 产品目标

### 3.1 目标用户

- 希望安全引入 AI Agent 与内部自动化的企业和团队；
- 需要中文界面、企业身份系统和统一模型治理的部署管理员；
- 使用组织模型或个人模型完成知识工作、应用构建与协作的终端用户；
- 需要长期维护 Cloudflare OS 分叉并持续吸收上游更新的工程团队。

### 3.2 一期目标

- 完成 Cloudflare OS 到 Softmatrix OS 的完整用户可见品牌改造；
- 支持 `zh-CN` 和 `en` 两种语言，并提供可靠的语言回退机制；
- 每个部署支持配置一个通用 OIDC 身份源，同时保留现有认证方式；
- 支持组织共享模型、管理员模型策略和可控 BYOK；
- 首选部署目标保持 Cloudflare Workers；
- 保持未来基于 `workerd` 私有部署的可能性，不新增一期交付承诺；
- 保持 Apache-2.0 许可证和上游归属信息，建立可持续上游同步流程。

### 3.3 非目标

- SAML 2.0、SCIM、OIDC 群组角色映射和完整 RBAC；
- 完整多租户组织模型；
- 请求级智能模型路由、自动故障切换、配额计费和成本中心；
- 简体中文与英文之外的语言；
- 自动翻译用户内容、历史对话、Gadget 内容或第三方数据；
- 为 `workerd` 私有部署进行额外功能开发；
- 改变 Gatekeeper 的能力授权、操作模拟或人工审批安全模型。

## 4. 已确认假设

1. 一期以 Cloudflare Workers 为首选生产运行环境。
2. 一个 Softmatrix OS 部署对应一个组织边界，并配置至多一个通用 OIDC issuer。
3. OIDC 以经过验证的规范化邮箱作为 Softmatrix OS 账号唯一标识。
4. OIDC 首次登录使用 JIT Provisioning，但受注册开关和可选邮箱域名白名单约束。
5. 管理员继续通过部署配置中的邮箱名单识别；群组到角色映射留到二期。
6. 组织共享模型与用户 BYOK 可以并存，管理员决定是否允许 BYOK。
7. 英文是翻译资源的最终回退语言。
8. 用户选择的界面语言也作为 Agent 默认回复语言；用户的显式语言要求优先。
9. Softmatrix OS 是长期维护的上游分叉，而不是一次性重命名版本。

## 5. 用户故事

### 5.1 终端用户

- 作为首次访问者，我希望系统根据浏览器语言显示中文或英文，以便直接理解登录流程。
- 作为登录用户，我希望手动切换语言并保存偏好，以便跨会话保持一致体验。
- 作为企业员工，我希望使用组织 OIDC 登录，而不需要创建独立密码。
- 作为模型用户，我希望使用管理员提供的模型，以便无需管理 API Key。
- 在管理员允许时，我希望配置自己的模型密钥，以便使用个人额度或自托管模型。
- 当模型不可用时，我希望看到明确原因和处理入口，而不是被静默切换模型。

### 5.2 部署管理员

- 我希望配置 OIDC issuer、client ID、client secret 和域名白名单，以接入企业身份源。
- 我希望关闭密码登录，确保组织只使用批准的身份入口。
- 我希望配置组织模型目录、默认模型和供应商启停策略。
- 我希望允许或禁止 BYOK，并确保该策略在服务端强制执行。
- 我希望升级时仍能保留 Softmatrix OS 定制并持续合并上游安全修复。

## 6. 功能需求

### 6.1 品牌与上游治理

| ID | 需求 | 验收标准 |
|---|---|---|
| BR-01 | 产品用户可见名称统一为 Softmatrix OS | 登录页、页面标题、导航、空状态、错误页、导出名称和文档不存在误导性的 Cloudflare OS 品牌残留 |
| BR-02 | 品牌常量集中管理 | 默认站点名、Logo、产品 URL 和支持信息不再散落在业务组件中 |
| BR-03 | 保留可部署级定制能力 | 现有自定义站点名、Logo、主题和管理员配置继续工作 |
| BR-04 | 建立上游同步机制 | 保留只读 `upstream` 远程、同步说明、冲突热点清单和定期同步节奏 |
| BR-05 | 清晰标注派生关系 | README 和 NOTICE/第三方声明说明 Softmatrix OS 基于 Cloudflare OS 修改，不暗示 Cloudflare 背书 |

### 6.2 国际化

| ID | 需求 | 验收标准 |
|---|---|---|
| I18N-01 | 支持 `zh-CN` 与 `en` | 两套语言资源均可独立构建并覆盖一期范围内界面 |
| I18N-02 | 自动语言检测 | 未登录用户首次访问时，中文浏览器使用 `zh-CN`，其他语言使用 `en` |
| I18N-03 | 手动切换语言 | 用户可在设置入口切换语言，界面无需重新登录即可生效 |
| I18N-04 | 持久化偏好 | 未登录偏好存本地；登录偏好存用户配置并覆盖浏览器默认值 |
| I18N-05 | 英文回退 | 缺失中文翻译时显示英文，不显示原始翻译键，不阻断页面 |
| I18N-06 | 本地化区域格式 | 日期、时间、数字和金额使用当前区域规则，存储与 API 数据保持语言无关 |
| I18N-07 | 覆盖完整核心界面 | 登录注册、工作区、聊天、Gadget、Blueprint、连接器、模型、管理员后台、弹窗、Toast、错误页及无障碍标签完成迁移 |
| I18N-08 | Agent 默认语言跟随 | Agent 系统上下文包含用户语言偏好；用户显式要求其他语言时服从用户 |
| I18N-09 | 翻译质量门禁 | CI 检查翻译键缺失、无效插值变量和不可解析资源；禁止新增写死的核心可见文案 |

国际化不翻译用户输入、历史消息、Gadget 内容、代码、模型输出或第三方连接器返回内容。

### 6.3 通用 OIDC SSO

| ID | 需求 | 验收标准 |
|---|---|---|
| SSO-01 | 标准 OIDC 登录 | 使用 Authorization Code + PKCE，并验证 `state` 和 `nonce` |
| SSO-02 | Discovery 与签名验证 | 通过 issuer Discovery 获取端点/JWKS；校验签名、issuer、audience、有效期和授权码绑定 |
| SSO-03 | 可信邮箱身份 | 仅接受 `email_verified=true` 且格式有效的邮箱；按小写规范化邮箱关联账号 |
| SSO-04 | JIT Provisioning | 首次登录仅在注册开启且满足可选域名白名单时建号 |
| SSO-05 | 账号去重 | 相同规范化邮箱通过 OIDC、Access 或现有 OAuth 登录时进入同一账号 |
| SSO-06 | 单部署单 OIDC | 一期每个部署配置至多一个 issuer、client ID、client secret 和显示名称 |
| SSO-07 | 安全配置 | client secret 只能存在于 Secrets/环境变量，不进入 AdminConfig、RPC、日志或前端资产 |
| SSO-08 | 登录方式治理 | 管理员可启用 OIDC，并通过既有配置控制密码登录及现有 OAuth 登录入口 |
| SSO-09 | 失败处理 | 用户获得本地化、无敏感信息的错误；服务端记录稳定错误码和必要安全上下文 |
| SSO-10 | 兼容性验证 | 至少完成 Keycloak、Microsoft Entra ID、Okta 三者中的两种端到端联调 |

OIDC Discovery 和 JWKS 可以按 HTTP 缓存语义有限缓存，但任何故障场景都不得跳过签名或
声明验证。OIDC 配置仍属于部署级安全配置，不能由已登录管理员通过普通 Admin API 动态修改。

### 6.4 多 LLM 与模型治理

| ID | 需求 | 验收标准 |
|---|---|---|
| LLM-01 | 保留现有供应商 | OpenAI、Anthropic、Google、Workers AI、Ollama 继续可用，并支持既有兼容 API URL 能力 |
| LLM-02 | 组织模型目录 | 管理员可配置供应商、模型 ID、显示名称、上下文窗口、启停状态和组织默认模型 |
| LLM-03 | 组织共享密钥 | 组织模型密钥仅存服务端 Secrets/部署环境；前端只看到配置状态，不得到密钥 |
| LLM-04 | BYOK 策略 | 管理员可全局允许或禁止 BYOK；服务端拒绝被策略禁止的新增或使用请求 |
| LLM-05 | 统一模型列表 | 组织模型与个人模型统一展示，并清晰标注来源、可用状态和是否为默认/首选模型 |
| LLM-06 | 默认与首选模型 | 新用户默认使用组织默认模型；用户可保存个人首选模型并在对话中手动切换 |
| LLM-07 | 凭据生命周期 | BYOK 支持添加、连接测试、覆盖和删除；任何读取接口都不回传明文密钥 |
| LLM-08 | 明确故障反馈 | 区分不可用、限流、余额不足、凭据失效和策略拒绝，提供重试、切换或更新入口 |
| LLM-09 | 禁止静默切换 | 一期模型故障不自动切换到其他模型，避免成本、数据区域和行为意外变化 |
| LLM-10 | 使用元数据 | 记录供应商、模型、Token 与估算成本；不记录密钥、完整提示词或响应正文 |

## 7. 关键流程

### 7.1 语言选择

1. 首次访问读取浏览器语言并映射为 `zh-CN` 或 `en`。
2. 未登录语言选择写入本地存储。
3. 登录后读取用户语言偏好；存在时覆盖浏览器和本地默认值。
4. 用户切换语言后立即更新前端上下文，并异步保存用户偏好。
5. Agent 请求携带稳定的语言代码，由系统提示设定默认回复语言。

### 7.2 OIDC 登录

1. 浏览器请求启动 OIDC 登录。
2. 后端生成短期登录尝试，绑定 PKCE verifier、`state`、`nonce` 和回调上下文。
3. 浏览器跳转到身份提供商并完成认证。
4. 回调校验 `state`、授权码、Token 签名与声明，并确认已验证邮箱。
5. 后端按注册开关和域名白名单执行 JIT 策略。
6. 规范化邮箱定位或创建用户，签发 Softmatrix OS 会话。
7. 任何失败返回稳定错误码；日志不包含 Token 或完整声明。

### 7.3 模型调用

1. 用户从统一模型目录选择模型。
2. 服务端校验模型状态、组织策略、用户权限和 BYOK 开关。
3. 服务端解析组织共享凭据或用户隔离的 BYOK 凭据。
4. 调用现有模型适配层和供应商 API。
5. 向用户流式返回响应，并记录允许的使用元数据。
6. 故障按稳定错误类别返回；用户显式决定重试或切换模型。

## 8. 系统设计

### 8.1 组件边界

#### 国际化模块

- 前端拥有统一的 locale 上下文、语言资源加载、插值和格式化接口；
- 用户语言偏好通过已有 Authenticated API 扩展持久化；
- 后端错误返回稳定错误码和参数，而不是待展示英文句子；
- Agent 系统上下文接收 BCP 47 语言标签，不耦合具体 UI 文案库。

#### 统一身份模块

- 在现有 `auth` 目录和 Public API 登录能力上扩展 OIDC；
- 复用现有 PendingLogin/回调 rendezvous、用户 Durable Object 和会话机制；
- 不把身份认证伪装成普通数据 Gatekeeper，也不让身份提供商获得额外资源能力；
- 安全配置继续由环境变量和 Secrets 驱动，避免受损管理员会话修改认证根配置。

#### 模型策略模块

- 保留现有 `AiModelProvider`、模型适配层、用户模型存储和 AI Gateway 模式；
- 增加部署级组织模型目录和服务端策略解析层；
- 对前端暴露脱敏后的统一模型视图，不暴露凭据存储细节；
- 所有新增共享 RPC 类型遵循上游导出成员文档和 promise pipelining 约定。

### 8.2 配置边界

| 配置类型 | 存储位置 | 示例 |
|---|---|---|
| 安全根配置 | Cloudflare Secrets / 环境变量 | OIDC client secret、组织模型 API Key、Access audience |
| 部署硬策略 | 环境变量或部署清单 | OIDC issuer、BYOK 是否允许、允许的模型供应商 |
| 非敏感管理配置 | AdminConfig | 默认模型 ID、展示名称、可见模型、站点品牌 |
| 用户偏好 | User Durable Object | 语言、首选模型、个人 BYOK 模型配置 |
| 浏览器临时偏好 | Local Storage | 未登录语言选择 |

实现计划必须确保：任何安全根配置都不能通过 Admin API 读取；非敏感配置不得包含可用于推理或
身份交换的凭据。

### 8.3 项目结构目标

实际文件名可在实施计划中按现有代码模式细化，但职责必须遵循以下边界：

```text
packages/workshop-frontend/src/
  i18n/                  # locale、资源、格式化和测试工具
  components/auth/       # OIDC 与现有登录入口 UI
  routes/providers.tsx   # 统一组织/个人模型目录

packages/workshop-backend/src/
  auth/                  # OIDC 配置、协议流程和身份校验
  model-policy/          # 组织目录、BYOK 策略和脱敏视图
  user.ts                # 仅保留用户偏好/个人模型的持久化编排

packages/workshop-shared/src/
  api.ts                 # 最小化、文档完整的共享 RPC 类型

docs/
  superpowers/specs/     # 产品规格与设计
  decisions/             # 实施阶段产生的不可逆架构决策
```

## 9. 安全与隐私要求

- OIDC 必须使用 Authorization Code + PKCE、`state`、`nonce` 和严格回调 URL；
- 必须校验 Token 签名、issuer、audience、时间声明和 `email_verified`；
- 密钥不得进入浏览器包、RPC 返回、客户端错误、分析事件或日志；
- BYOK 继续使用用户 Durable Object 隔离，只允许覆盖或删除，不允许读回明文；
- 模型和身份策略必须由服务端强制执行；
- 不改变 Gatekeeper capability-based security 和 Human-in-the-loop 机制；
- 日志禁止包含 Token、API Key、授权请求头、完整 OIDC 声明、提示词和模型响应；
- 认证与模型失败应使用有界、可索引的错误码和非敏感上下文字段；
- 任何新依赖必须经过维护状态、许可证、供应链和 Workers Runtime 兼容性审查。

## 10. 错误处理与可观测性

### 10.1 稳定错误类别

- 身份：`OIDC_CONFIG_INVALID`、`OIDC_STATE_INVALID`、`OIDC_TOKEN_INVALID`、
  `OIDC_EMAIL_UNVERIFIED`、`SIGNUP_NOT_ALLOWED`、`EMAIL_DOMAIN_NOT_ALLOWED`；
- 模型：`MODEL_DISABLED`、`MODEL_CREDENTIAL_INVALID`、`MODEL_RATE_LIMITED`、
  `MODEL_BALANCE_EXHAUSTED`、`MODEL_PROVIDER_UNAVAILABLE`、`BYOK_DISABLED`；
- 国际化：翻译资源错误只在开发/监控中报告，用户界面回退英文。

错误码是前后端契约；用户文案由前端按当前语言生成。未知错误显示通用消息和关联 ID，
服务端保留不含敏感数据的诊断信息。

### 10.2 降级原则

- 翻译缺失：回退英文，不阻断功能；
- OIDC Discovery/JWKS 暂时不可用：使用仍在有效期内的缓存或失败关闭，绝不跳过验证；
- 模型失败：保留当前选择并提供处理入口，不静默切换供应商或模型；
- 组织配置错误：管理员看到可操作诊断，普通用户只看到安全的不可用提示。

8. 不删除上游专利条款或贡献者归属，不擅自改变上游文件的许可证头。

## 13. 代码与交付边界

### 13.1 始终执行

- 使用 pnpm；
- 对逻辑和行为变更先写失败测试，再实现；
- 对 `workshop-shared` 的每个导出成员写文档注释；
- 保持 Kernel 和 RPC 修改小而清晰，复用已有机制；
- 对 RPC stub 正确释放，并保持 Cap'n Web promise pipelining；
- 对用户可见文案使用翻译键，对错误使用稳定错误码；
- 提交前检查 staged diff、敏感信息、测试、lint 和 build；
- 按品牌/i18n、身份、模型、Kernel/RPC、文档拆分可审查提交。

### 13.2 实施时必须先评审

- 新增第三方依赖；
- 修改 Durable Object 数据结构或迁移；
- 扩展公开 RPC；
- 修改 CI、发布清单或生产部署参数；
- 改变认证账号主键、会话格式或 Gatekeeper 权限模型；
- 在一期范围外引入 SAML、SCIM、自动模型路由或多租户能力。

### 13.3 禁止事项

- 提交密钥、Token、`.env` 或 `.dev.vars`；
- 将安全根配置放入可由普通管理员会话读取或修改的 AdminConfig；
- 删除失败测试来通过 CI；
- 静默降级身份校验或模型选择；
- 大规模重写 Workshop Backend Kernel；
- 删除或替换上游 Apache-2.0 许可证及归属信息。

### 13.4 代码风格

- 延续各 package 现有 TypeScript/React 风格，不在功能提交中混入全仓格式化；
- 类型、类和 React 组件使用 `PascalCase`，函数、变量和翻译命名空间使用 `camelCase`；
- 稳定错误码使用 `UPPER_SNAKE_CASE`，语言标签使用 BCP 47（`zh-CN`、`en`）；
- 前端沿用 Kumo UI 和 Phosphor 图标；后端导出 API 必须有解释用途与安全边界的文档注释；
- 错误契约传递代码和有界参数，不传递可直接展示的英文消息。

```ts
/** A stable, locale-independent failure returned when a model policy rejects a request. */
export type ModelPolicyError = {
  code: "MODEL_DISABLED" | "BYOK_DISABLED";
  modelId?: string;
};

export function assertModelAllowed(modelId: string, policy: ModelPolicy): void {
  if (!policy.enabledModelIds.has(modelId)) {
    throw new PolicyError({ code: "MODEL_DISABLED", modelId });
  }
}
```

## 15. 一期发布成功标准

以下条件必须全部满足：

1. 新部署可使用中文或英文完成登录、创建工作区、选择模型并完成一次 Agent 任务；
2. 语言偏好跨会话保持，英文回退可靠，核心流程无明显未国际化文案；
3. OIDC、Cloudflare Access、现有 OAuth 和可选密码登录均按部署策略工作且无回归；
4. OIDC 通过至少两个目标 IdP 的联调，并通过协议与攻击场景测试；
5. 管理员能控制组织模型、默认模型、供应商启停和 BYOK 权限；
6. 组织共享模型与个人 BYOK 均能完成真实推理，禁止策略无法被客户端绕过；
7. 客户端资产、RPC、日志和错误报告中不存在明文身份或模型密钥；
8. `pnpm lint`、`pnpm test`、`pnpm build` 全部通过；
9. Apache-2.0 LICENSE、上游归属、修改声明和第三方许可证清单完成审查；
10. 提供中英文部署、SSO、模型配置、运维和升级文档。

## 16. 风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 上游快速变化导致合并冲突 | 延误、安全修复难同步 | 最小化 Kernel/RPC 改动；维护冲突热点；固定同步节奏 |
| UI 文案分散且数量大 | 翻译遗漏、回归 | 先迁移英文资源；CI 完整性检查；按路由分批验收 |
| 不同 OIDC 提供商声明差异 | 登录失败或账号重复 | 严格依赖标准声明；选择两种 IdP 联调；非标准映射延后 |
| OIDC 与已有 OAuth 账号关联错误 | 账号接管风险 | 只信任已验证邮箱；统一规范化；增加冲突和重放测试 |
| 组织模型和 BYOK 策略分叉 | 策略绕过、体验混乱 | 服务端单一策略解析层；前端只消费脱敏统一视图 |
| 模型供应商 API 变化 | 推理失败 | 复用 Pi 与现有适配层；供应商契约测试；错误明确不静默切换 |
| 品牌改造误删上游归属 | 许可证或商标风险 | 合规清单、README 派生声明、LICENSE/NOTICE 自动检查 |

## 17. 方案比较与决策

### 17.1 已选择：模块化增强型分叉

- **优点**：复用上游能力；安全边界清晰；交付速度和长期维护成本平衡；便于分阶段审查；
- **代价**：需要建设统一配置和策略层，并长期维护上游同步纪律。

### 17.2 未选择：最小化品牌分叉

- **优点**：最快交付；
- **拒绝原因**：配置和文案继续分散，企业认证与模型治理缺乏统一服务端边界，后续维护成本高。

### 17.3 未选择：平台级重构

- **优点**：可一次性获得多租户、RBAC、SCIM、计费和智能路由；
- **拒绝原因**：显著扩大 Kernel/RPC 改动和上游合并成本，不符合一期目标。

## 18. 二期候选路线图

- SAML 2.0、SCIM、OIDC 群组角色映射和细粒度 RBAC；
- 多租户组织空间与租户级策略；
- 模型配额、预算、审计报表和成本中心；
- 自动故障切换、按任务路由和多供应商负载均衡；
- 更多语言和连接器管理 UI 本地化；
- 完整 `workerd` 私有化部署支持。

二期项目必须分别形成独立规格和实施计划，不得在一期实施中隐式扩展。
